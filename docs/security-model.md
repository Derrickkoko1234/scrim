# Scrim for Git — Security Model and Threat-Model Review

This document is the Milestone M5 threat-model review for Scrim for Git. It specifies the trust boundaries, authentication and key-management controls, cryptographic constructions, access-control enforcement across transports and Git hooks, non-goals and residual oracles, and the mapping from security invariants to automated tests.

All claims below describe the implementation in `scrim-policy`, `scrim-crypto`, `scrim-cli`, and `scrim-server`.

---

## 1. Architecture & Trust Boundaries

Scrim splits enforcement between client-side cryptography (which protects secret values and encrypted private files even when stored on untrusted Git remotes) and server-side policy enforcement on `scrim-server` (which gates repository access, branch visibility, server-side blob withholding, and push guards).

```text
+-------------------------------------------------------------------+
| Developer Workstation / CI Runner                                 |
|  - git + `scrim` CLI (`filter-process`, `clone`, `mirror`, ...)   |
|  - `~/.config/scrim/config.toml` (0600), `identity.age` (0600)    |
|  - Opt-in: private key in macOS Keychain / Windows Cred. Manager  |
|  - CI zero-disk mode: `SCRIM_KEY` env var                         |
|  - Tokens passed to `git` only via `GIT_CONFIG_*` env vars        |
+----------------------------+--------------------------------------+
                             |
      Smart HTTP (TLS proxy) |   Git over SSH (`russh`, `ring`)
                             v
+-------------------------------------------------------------------+
| `scrim-server`                                                    |
|  - Auth middleware (SHA-256 token lookup before gzip/repo resolve)|
|  - SSH handler (Ed25519/ECDSA-only, per-`exec` re-verification)   |
|  - `repo_path` canonicalizer (no traversal, symlinks out,         |
|    alternates, `.git`, `commondir`, or `reftable`)                |
|  - Isolated `git upload-pack` / `receive-pack` (`env_clear()`)    |
|  - `HookDir` (0700): `pre-receive` + `pack-objects` symlinks,     |
|    Unix socket (or loopback TCP) with mutual SHA-256 proofs       |
|  - `gix` isolated object-graph walk (withholding)                 |
+---------------+--------------------+------------------+-----------+
                |                    |                  |
                v                    v                  v
+-----------------------+  +------------------+  +------------------+
| PostgreSQL (`sqlx`)   |  | Redis (`fred`)   |  | Cloudflare R2    |
| - Authoritative rules |  | - Policy cache   |  | - SigV4 HTTPS    |
| - SHA-256 token hashes|  | - Epoch-keyed    |  | - Bare repo tars |
| - SSH key fingerprints|  | - Auth NEVER     |  | - `pg_dump`      |
| - Append-only         |  |   cached         |  | - SHA-256 + size |
|   `audit_log`         |  | - Fail-open to   |  |   verified on    |
+-----------------------+  |   Postgres       |  |   restore        |
                           +------------------+  +------------------+

+-------------------------------------------------------------------+
| Untrusted External Mirrors (e.g. GitHub)                          |
|  - Fed only by `scrim mirror` (public refs only, explicit         |
|    `<ref>:<ref>`, history verified for `SCRIMFILE\0` blobs)       |
+-------------------------------------------------------------------+
```

### Trust Boundaries & Component Roles

| Boundary / Component | Trust Assumptions & Isolation Controls |
|---|---|
| **Developer Workstation** | Trusted for plaintext while unlocked. `~/.config/scrim` (or resolved `SCRIM_CONFIG_DIR` / `XDG_CONFIG_HOME`) is created with `0700` permissions on Unix; `config.toml` and `identity.age` are written atomically via `O_CREAT \| O_EXCL` temporary files with mode `0600` and renamed into place ([crates/scrim-cli/src/config.rs](../crates/scrim-cli/src/config.rs)). Members may opt in to keeping the private key in the OS keychain instead of `identity.age` (see *Workstation Key Storage* below). |
| **CI Runners** | Trusted for scoped secrets at job runtime. Machine accounts supply their `age` identity in `SCRIM_KEY` without writing `identity.age` to disk (precedence: `--key-file` > `SCRIM_KEY` > `SCRIM_KEY_FILE` > OS keychain when enabled > `identity.age`; `--key-file` explicitly blanks `SCRIM_KEY` in `FilterEnv` so process environments do not leak). |
| **`scrim-server` Process & Git Subprocesses** | `scrim-server` runs behind a TLS reverse proxy for HTTP and binds SSH directly. All spawned `git` subprocesses run with `env_clear()` (retaining only `PATH`), `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, and `GIT_NO_REPLACE_OBJECTS=1` (in `run_isolated_git`), preventing host/repo Git config or replace refs from altering behavior ([crates/scrim-server/src/git_service.rs](../crates/scrim-server/src/git_service.rs)). |
| **Server Hook Boundary (`HookDir`)** | A `0700` temporary directory (placed under `XDG_RUNTIME_DIR` or `TMPDIR`/`/tmp`, checked against `MAX_UNIX_SOCKET_PARENT_BYTES = 68` so `sun_path` fits) holds `pre-receive` and `pack-objects` links to the `scrim-server` binary. Hook presence and executability are verified before every `receive-pack` and every withheld `upload-pack`. Over Unix domain sockets (or loopback TCP on non-Unix), both sides prove knowledge of a 32-byte random per-request token without transmitting it, using domain-separated SHA-256 proofs compared with `subtle::ConstantTimeEq`. Up to `MAX_REJECTED_CALLBACK_CONNECTIONS = 16` bad connections are dropped without locking out the real hook ([crates/scrim-server/src/pre_receive.rs](../crates/scrim-server/src/pre_receive.rs), [crates/scrim-server/src/pack_withhold.rs](../crates/scrim-server/src/pack_withhold.rs)). |
| **Bare Repository Root** | `resolve_bare_repo` validates undecoded path segments (`is_valid_repo_path`, rejecting `.`, `..`, `%`, whitespace, and `api/`), canonicalizes symlinks so intra-root symlinks map to the target's `canonical_key` and out-of-root escapes return a generic `404`, and rejects any repository containing `.git`, `commondir`, `reftable`, `objects/info/alternates`, `objects/info/http-alternates`, symlinked `HEAD`, `refs/heads/.invalid`, or unsearchable `objects`/`refs` ([crates/scrim-server/src/repo_path.rs](../crates/scrim-server/src/repo_path.rs)). |
| **PostgreSQL (`PgPolicyStore`)** | Authoritative source of members, active/revoked SHA-256 token hashes (`member_tokens`), SSH key fingerprints (`member_ssh_keys`), groups, branch rules, path rules, secret scopes, and `audit_log`. Mutations execute transactionally with `audit_log` inserts (`actor_member_id` uses `ON DELETE SET NULL` so records survive). The last active admin cannot be revoked ([crates/scrim-server/src/policy_store.rs](../crates/scrim-server/src/policy_store.rs)). |
| **Redis (`CachedPolicyStore`)** | Untrusted performance cache for `MemberRepoPolicy` only (`fred` client, `redis://` or TLS `rediss://`). Entries are keyed by `scrim:policy:v1:e{epoch}:m{member_id}:r{sha256(repo_key)}` and re-validated via `BranchPolicy::compile` / `WithholdPolicy::compile` on read. **Authentication and revocation are never cached.** Any Redis outage or corrupt/oversized (`> 4 MiB`) entry falls back to PostgreSQL, which still fails closed on DB error ([crates/scrim-server/src/policy_cache.rs](../crates/scrim-server/src/policy_cache.rs)). |
| **Cloudflare R2 Backups** | Untrusted storage outside the server boundary after upload. Uploads/downloads use AWS SigV4 (`AWS4-HMAC-SHA256`) over HTTPS with HTTP redirects disabled (`reqwest::redirect::Policy::none()`). Restores verify manifest structure, exact byte counts, and SHA-256 digests before archive extraction or `pg_restore` ([crates/scrim-server/src/backup.rs](../crates/scrim-server/src/backup.rs)). |
| **External Mirrors (e.g., GitHub)** | Untrusted for confidentiality. Only public branches/tags (`audience = everyone`) and client-side `SCRIMFILE\0` encrypted blobs may be pushed via `scrim mirror` ([crates/scrim-cli/src/mirror_cmd.rs](../crates/scrim-cli/src/mirror_cmd.rs)). |

## 2. Authentication & Key Management

### API Bearer Tokens (HTTP & Admin API)

- **Format & Storage:** Issued tokens are `scrim_` followed by 64 lowercase hex characters (32 random bytes from `getrandom`). Only the 32-byte SHA-256 digest is stored in `member_tokens.token_hash` (with `CHECK (octet_length(token_hash) = 32)`). Plaintext tokens are returned once at creation/issuance and never stored or logged.
- **Verification:** `require_auth` ([crates/scrim-server/src/auth.rs](../crates/scrim-server/src/auth.rs)) accepts a single `Authorization` header (`Bearer <token>` or `Basic <base64>` up to `MAX_AUTHORIZATION_HEADER_BYTES = 4096`; tokens capped at `MAX_TOKEN_BYTES = 1024`), rejecting duplicate `Authorization` headers to prevent proxy/parser smuggling. It hashes the candidate token via `sha256_zeroizing` and verifies it against the `PolicyStore` **before** `RequestDecompressionLayer` (gzip decompression) or repository path resolution.
- **Constant-Time & Fail-Closed Guarantees:** `TokenAuth` (single-token mode) and `MemoryPolicyStore` compare 32-byte digests with `subtle::ConstantTimeEq` (`MemoryPolicyStore` scans all tokens even after a match). `PgPolicyStore` queries the unique `token_hash` index filtering `mt.revoked_at IS NULL AND m.revoked_at IS NULL`. Store failures return HTTP `500`, never `200` or `401`. After verification, `require_auth` removes the `Authorization` header from the request so downstream handlers never observe or forward it.
- **Client Token Scoping:** `scrim clone` ([crates/scrim-cli/src/clone_cmd.rs](../crates/scrim-cli/src/clone_cmd.rs)) and `git_extra_header_env` ([crates/scrim-cli/src/git.rs](../crates/scrim-cli/src/git.rs)) pass the bearer token to `git` exclusively via `GIT_CONFIG_COUNT` / `GIT_CONFIG_KEY_<n>` / `GIT_CONFIG_VALUE_<n>` scoped to `http.<server_base_url>/.extraHeader` with `GIT_TERMINAL_PROMPT=0`. The token is never placed in argv, remote URLs, or `.git/config`, and saved tokens for one server URL are refused when cloning from a different host.

### SSH Public Keys (Git over SSH)

- **Transport & Allowed Algorithms:** `serve_ssh` ([crates/scrim-server/src/ssh_server.rs](../crates/scrim-server/src/ssh_server.rs)) uses `russh` backed by `ring`, offering `MethodKind::PublicKey` only (`max_auth_attempts: 6`, `INACTIVITY_TIMEOUT = 600s`, `MAX_SESSION_CHANNELS = 8`). Only **Ed25519** and **ECDSA (`nistp256`, `nistp384`)** are accepted (`is_allowed_ssh_key_algorithm`); DSA, RSA (to avoid timing side-channel dependencies), security-key (`sk-*`), and certificate types are rejected.
- **Canonicalization & Per-`exec` Re-verification:** Registered keys are canonicalized without comments and indexed by SHA-256 fingerprint (`SHA256:...`). Because SSH connections can multiplex channels across time, `serve_exec` re-queries `authenticate_ssh_key(&fingerprint)` on every `exec` request, cutting off multiplexed sessions immediately if the member or SSH key is revoked.
- **Command Surface Isolation:** `shell_request`, `pty_request`, `subsystem_request`, `x11_request`, `tcpip_forward`, and `streamlocal_forward` are unconditionally refused. Only `env_request` for sanitized `GIT_PROTOCOL` (up to `MAX_ENV_REQUESTS_PER_CHANNEL = 16`) and `exec_request` matching `git-upload-pack '<repo>'` or `git-receive-pack '<repo>'` (`MAX_EXEC_COMMAND_BYTES = 1024`, parsed directly by `parse_git_ssh_command` with no shell) are permitted.
- **Host Key Protection:** `load_or_create_ssh_host_key` opens existing keys with `O_NOFOLLOW | O_NONBLOCK`, rejects symlinks, encrypted keys, unsupported algorithms, and files over `16 KiB`, and creates new Ed25519 host keys via a `0600` temporary file linked atomically with `hard_link`.

### Age X25519 Identities & Memory Handling

- **Identity & Public Key Validation:** `MemberIdentity` and `MemberPublicKey` ([crates/scrim-crypto/src/identity.rs](../crates/scrim-crypto/src/identity.rs)) wrap `age::x25519` (`age 0.11.5`). `MemberPublicKey::parse` enforces strict canonical lowercase BIP-173 Bech32 (`age1...`, no whitespace or uppercase; `age` rejects invalid checksums and all-zero / non-canonical X25519 encodings). `MemberIdentity::Debug` prints `MemberIdentity([REDACTED])`, and `InvalidIdentity` / `InvalidPublicKey` errors never echo the input.
- **Memory Zeroization:** Secrets, tokens, decoded HTTP `Basic` credentials, `ScopeDataKey`, `GroupDataKey`, and decrypted plaintexts are held in `SecretString` (`secrecy 0.10.3`) and `Zeroizing` (`zeroize 1.9.2`). SHA-256 state is wiped via `sha2`'s `zeroize` feature (`sha256_zeroizing`). `serialize_secrets`, `decrypt_wrapped_payload`, `candidate_token_hash`, and `append_zeroizing` pre-size buffers so `Vec` reallocations do not leave unzeroized copies in freed heap memory.

### Workstation Key Storage

- **Default (`identity.age`):** `scrim keygen` writes the age identity to `identity.age` next to `config.toml` (`0600`, atomic rename, `0700` directory on Unix). Anyone who can read the member's files, including any process running as that user and unencrypted backups of the home directory, can read the key.
- **Opt-in OS keychain:** `scrim keygen --keychain` stores a new identity, and `scrim keychain enable` / `scrim keychain disable` move an existing one, between `identity.age` and the platform keychain through the `keyring` crate's native backends only: the macOS Keychain (`apple-native`) and the Windows Credential Manager (`windows-native`). Entries use service `scrim-for-git` and account `<member>@<server URL>` (from `whoami` at the time the key is stored), and `config.toml` records that account as `keychain_account`; an absent field means file storage, so older configs are unchanged. Every other platform refuses keychain mode with "OS keychain storage is not supported on this platform": Linux kernel keyrings are not persistent (keys expire, so the only copy of a key could be lost) and Secret Service needs D-Bus.
- **Data-loss safety:** each move writes the destination, reads it back and compares it before recording the new mode in `config.toml`, and only then deletes the source; the file direction reuses the atomic `0600` writer. A different key already at the destination is never overwritten, and re-running after an interruption resumes. In keychain mode a failed or empty keychain read is an error, never a silent fallback to a plaintext `identity.age`. `SCRIM_KEY`, `SCRIM_KEY_FILE` and `--key-file` still take precedence ([crates/scrim-cli/src/keychain.rs](../crates/scrim-cli/src/keychain.rs)).
- **What keychain mode protects against:** the plaintext key no longer sits in the home directory, so it is not exposed by file backups, dotfile sync, accidental commits or copies of `~/.config`, or by other OS accounts and offline disk access when the keychain is locked (on macOS the login keychain is encrypted with the user's password; on Windows, Credential Manager entries are DPAPI-protected per user).
- **What it does not protect against:** malware or any process running as the member while the keychain is unlocked (the keychain ACL or a single user prompt is the only barrier, and `scrim` itself must read the key into memory to use it), or root/administrator access to a running session. Removing `identity.age` after a move uses an ordinary file delete, so earlier copies may remain recoverable from the disk, from backups, or in filesystem snapshots; regenerate the key (`scrim keygen --keychain --force`) and rotate scopes and group keys if the file may have been copied before.

## 3. Cryptographic Design

Scrim implements **no custom cryptographic primitives**. `scrim-crypto` and `scrim-server` compose audited crates only: `age` (`0.11.5`), `chacha20poly1305` (`0.10.1`), `aes-siv` (`0.8.0`), `sha2` (`0.11.1`), `hmac` (`0.13.0`), `ring` (via `russh`, `sqlx`, `fred`), `subtle` (`2.6.1`), `zeroize` (`1.9.2`), and `secrecy` (`0.10.3`). CI enforces `cargo-deny` ([deny.toml](../deny.toml)) against RustSec advisories, wildcard dependencies, non-`crates.io` sources, and license boundaries (`MIT OR Apache-2.0` on `scrim-cli`, `scrim-policy`, and `scrim-crypto`; `AGPL-3.0-only` isolated to `scrim-server`).

### Secrets (M2)

- **Key Hierarchy & Domain Separation:** Each scope has a 32-byte random `ScopeDataKey` (`getrandom`), wrapped per active recipient in `.scrim/keys/<scope>.toml` (`ScopeKeysFile`) using `age::x25519` over the domain-bound plaintext:
  ```text
  "scrim-scope-key-v1\n" || scope || "\n" || generation (decimal) || "\n" || key[32]
  ```
  Unwrapping verifies the version (`FILE_FORMAT_VERSION = 1`), scope, generation, and domain prefix with a bounded read (`MAX_WRAPPED_PAYLOAD_BYTES + 1`), defeating cross-scope substitution, generation rollback, or key-type confusion ([crates/scrim-crypto/src/scope_key.rs](../crates/scrim-crypto/src/scope_key.rs)).
- **AEAD Construction:** Secret bundles (canonical sorted JSON, up to `MAX_SECRETS_PER_SCOPE = 4096` keys, `MAX_SECRET_VALUE_BYTES = 256 KiB` each) are encrypted into `.scrim/secrets/<scope>.enc` using **XChaCha20-Poly1305** with a fresh 24-byte random nonce per write and 16-byte Poly1305 tag, binding AAD `"scrim-secrets-v1\n<scope>\n<generation>"` ([crates/scrim-crypto/src/secrets.rs](../crates/scrim-crypto/src/secrets.rs)).

### Encrypted Private Files (M3)

- **Group Key Wrapping:** Each group has a 64-byte random `GroupDataKey` wrapped per group member in `.scrim/group-keys/<group>.toml` (`GroupKeysFile`) under a distinct payload domain:
  ```text
  "scrim-group-key-v1\n" || group || "\n" || generation (decimal) || "\n" || key[64]
  ```
  so scope keys and group keys can never be swapped ([crates/scrim-crypto/src/group_key.rs](../crates/scrim-crypto/src/group_key.rs)).
- **Deterministic Authenticated Encryption (`SCRIMFILE\0`):** Private files (up to `MAX_PRIVATE_FILE_BYTES = 64 MiB`) are encrypted with deterministic **AES-256-SIV** (RFC 5297, `aes-siv 0.8.0`) into the binary blob format ([crates/scrim-crypto/src/file_crypto.rs](../crates/scrim-crypto/src/file_crypto.rs)):
  ```text
  "SCRIMFILE\0" (10B) || version u32 BE || generation u64 BE || group_len u16 BE || group || SIV tag (16B) || ciphertext
  ```
  The embedded NUL byte ensures Git treats blobs as binary (preventing CRLF or encoding corruption). S2V authenticates the vector `["scrim-file-v1", group, generation (u64 BE), repo_relative_path]` (each element separately), binding the ciphertext to its group, generation, and normalized path (`validate_file_path`, max `MAX_FILE_PATH_BYTES = 4096`).
- **Placeholder Envelopes:** Non-members receive a bounded readable placeholder ([crates/scrim-crypto/src/placeholder.rs](../crates/scrim-crypto/src/placeholder.rs)) wrapping the exact `SCRIMFILE\0` blob in 76-char base64 lines between `-----BEGIN SCRIM ENCRYPTED BLOB-----` and `-----END SCRIM ENCRYPTED BLOB-----` (`MAX_FILTER_INPUT_BYTES = 90 MiB` in `scrim filter-process`). On clean, `extract_placeholder` re-renders canonically and verifies the embedded header's group and generation against the text lines, rejecting any tamper or corruption; `FilterContext::clean` also requires `extracted.path == pathname`, rejecting `git mv` or copying a placeholder to a different path without holding the group key ([crates/scrim-cli/src/filter.rs](../crates/scrim-cli/src/filter.rs)).

## 4. Access-Control Guarantees & Enforcement

### Private Branches (M1 — HTTP & SSH)

- **Ref Hiding & Protocol Downgrade:** `BranchPolicy` ([crates/scrim-policy/src/branch_policy.rs](../crates/scrim-policy/src/branch_policy.rs)) compiles `refs/...` globs (`validate_ref_glob`, max `MAX_REF_GLOB_BYTES = 1024`, rejecting `!`, `^`, `..`, `//`, `@{`, control chars, whitespace, `.lock`). Overlapping rules intersect (a member must satisfy *every* matching rule). `HiddenRefPlan` emits static prefixes (`prefix/`) for simple prefix globs and enumerates repository refs with `!` negations for exact/complex globs. Whenever `visibility.is_enforced()` is true—even if an unsatisfied rule currently matches zero refs—`scrim-server` drops `GIT_PROTOCOL` so Git speaks **protocol v0** (because protocol v2 `fetch` ignores `allow*SHA1InWant` and accepts arbitrary `want <oid>`), and passes `uploadpack.allowTipSHA1InWant=false`, `uploadpack.allowReachableSHA1InWant=false`, `uploadpack.allowAnySHA1InWant=false`, and `transfer.hideRefs=...`.
- **`deepen-not` & Symbolic/Detached `HEAD` Guards:** `UploadPackRequestFilter` ([crates/scrim-server/src/git_service.rs](../crates/scrim-server/src/git_service.rs)) validates pkt-line framing up to the first `0000` flush and rejects any `deepen-not` line before `git upload-pack` sees it, preventing existence/reachability probing of hidden refs. `compute_visibility` ([crates/scrim-server/src/lib.rs](../crates/scrim-server/src/lib.rs)) rejects symbolic `HEAD` chains reaching a hidden ref (`403` HTTP / `"access denied"` SSH, max depth `MAX_SYMREF_DEPTH = 16`, failing closed on cycles), hides symbolic refs pointing to hidden branches without negating them, and hides detached `HEAD`.
- **`pre-receive` Checks 1–4 ([crates/scrim-server/src/pre_receive.rs](../crates/scrim-server/src/pre_receive.rs)):**
  - **Check 1 (Framing & Confinement):** Requires well-formed ref updates on UTF-8 `refs/...` names (at most `MAX_REF_UPDATES_PER_PUSH = 1000` updates, `MAX_PUSH_OPTIONS = 64`), and confines `GIT_OBJECT_DIRECTORY` / `GIT_QUARANTINE_PATH` inside canonical `repo_dir/objects`.
  - **Check 2 (Case-Insensitive Ref Authorization & Conflict Guard):** Authorizes every create, update, and delete with `BranchPolicy::is_ref_visible_case_insensitive`, rejects updates differing only in ASCII case from existing refs or other refs in the push (blocking case-insensitive FS collisions without leaking the hidden spelling), and rejects pushes to symbolic refs. **Never overridable.**
  - **Check 3 (Hidden-Object & Thin-Pack `REF_DELTA` Smuggling Guard):** Runs `receive.unpackLimit=1` so pushed objects remain quarantined. Any object reachable from pushed tips and not reachable from the member's `visible_refs` must exist in `GIT_QUARANTINE_PATH`, and any quarantined object that already exists in the main repository store (copied in by `index-pack --fix-thin` as a `REF_DELTA` base) must be reachable from `visible_refs`. **Never overridable.**
  - **Check 4 (Merge-Leak Guard):** Uses `BranchPolicy::is_ref_chain_at_least_as_visible_as` (`audience(target) ⊆ audience(source)`) across existing refs and other refs in the same push to block commits reachable only from narrower-audience refs from landing in wider refs. Overridable only by `-o scrim.allow-merge-leak=true`, which records `branch.merge_leak_override` (with up to 10 sample commit OIDs) in `audit_log`; if the audit write fails, the push is rejected.

### Secrets & Leak Prevention (M2)

- **Offline Access & Revocation Rotation:** Authorized members decrypt `.scrim/secrets/<scope>.enc` offline (`scrim secrets`, `scrim run`). On `scrim access revoke` / `scrim secrets sync`, `rotate_scope` ([crates/scrim-crypto/src/rotation.rs](../crates/scrim-crypto/src/rotation.rs)) generates a new `ScopeDataKey` at `generation + 1`, drops the revoked member from `.scrim/keys/<scope>.toml`, re-encrypts secrets with a fresh nonce, and outputs `rotated_secret_keys` so operators know which underlying credentials to rotate at their source.
- **`pre-receive` Check 5 (Plaintext `.env` & Credential Scan):** Runs for all members (admins included) on new commits (up to `MAX_SCANNED_COMMITS = 4096`; merges via combined diff `-c`) and direct blob/tree ref targets ([crates/scrim-server/src/secret_scan.rs](../crates/scrim-server/src/secret_scan.rs)). Rejects plaintext `.env` / `.env.*` files (except `.env.example`, `.env.sample`, `.env.template`, `.env.dist`, `.env.defaults`) and 7 high-confidence credential patterns (`scrim-api-token`, `age-secret-key`, `private-key-pem`, `aws-access-key-id`, `github-token`, `stripe-live-key`, `slack-token`) in the first `MAX_SCANNED_BLOB_BYTES = 1 MiB` of non-binary blobs (`BINARY_DETECTION_BYTES = 8 KiB` NUL check) using linear, non-backtracking byte checks. Matched bytes are never echoed. Overridable with `-o scrim.allow-secret-scan=true`, which records `secret_scan.override` (locations and rule names only) in `audit_log`, failing closed if audit logging fails.

### Encrypted Private Files (M3)

- **Filter Protocol & `.gitattributes` Parity:** `scrim filter-process` speaks Git's long-running `filter.<name>.process` protocol v2 ([crates/scrim-cli/src/filter.rs](../crates/scrim-cli/src/filter.rs)). `PathPolicy` ([crates/scrim-policy/src/path_policy.rs](../crates/scrim-policy/src/path_policy.rs)) and `validate_path_glob` ([crates/scrim-policy/src/path_glob.rs](../crates/scrim-policy/src/path_glob.rs)) mirror `.gitattributes` matching (root-anchored when `/` is present, `**/<pattern>` when absent; `{`/`}` disallowed because Git `wildmatch` treats braces literally).
- **Protected Metadata & Fail-Closed Overlaps:** `.git/**`, `.gitattributes`, and `.scrim/**` are unconditionally protected (`is_protected_metadata_path`) and rejected in path rules. Overlapping rules pointing to distinct groups fail closed with `PolicyError::AmbiguousPathRule`. Revocation (`scrim access revoke` / `scrim private sync`) invokes `rotate_group_key` and re-normalizes tracked plaintext files.

### Server-Side Blob Withholding (M4)

- **Isolated `gix` Graph Walk & `packObjectsHook`:** When a member has unsatisfied `WithholdPolicy` rules ([crates/scrim-policy/src/withhold_policy.rs](../crates/scrim-policy/src/withhold_policy.rs)), `git upload-pack` runs with `uploadpack.packObjectsHook` pointing to `pack-objects` in `HookDir` ([crates/scrim-server/src/pack_withhold.rs](../crates/scrim-server/src/pack_withhold.rs)). `ObjectGraph::open` opens the repository with `gix::open::Options::isolated().open_path_as_is(true).cli_overrides(["core.useReplaceRefs=false"])`, walks commits, trees (up to `MAX_TREE_DEPTH = 256`), and visible tags (up to `MAX_TAG_DEPTH = 32`, cycle-checked), and emits only commits, trees, tags, and blobs reached at at least one non-withheld path. Non-UTF-8 paths fail closed as withheld.
- **Filter, Delta, and Want Hardening:**
  - `uploadpackfilter.allow=false` with only `blob:none.allow=true` and `blob:limit.allow=true` enabled (`sparse:oid` is disabled to block OID-probing oracles).
  - `--thin` is stripped before running `git pack-objects --stdout`, preventing withheld blobs from acting as delta bases.
  - `select_objects` refuses any `want` that does not peel to a `Kind::Commit` (blocking direct blob and subtree wants).
  - `scrim clone` configures `--filter=blob:limit=2147483647` and non-cone sparse-checkout (`/*` with `!/<pattern>` or `!<pattern>`) before checkout.
- **`pre-receive` Check 6 (Withheld-Path & Blob Republishing Guard):** For members with withheld paths, **never overridable**:
  - Single-parent new commits may not touch any withheld path (matched case-sensitively and ASCII case-insensitively; non-UTF-8 paths fail closed).
  - Merge commits may take a withheld path unchanged from one parent `j` only if every other parent `i` left that path untouched since all `git merge-base --all` ancestors (failing closed if no merge base exists), blocking `-s ours` or historical reverts.
  - `find_withheld_only_blobs` verifies that no pushed blob (at a visible path, as a direct ref/tree target, or copied into quarantine as a `REF_DELTA` base) exists in visible repository history *only* at withheld paths (except `EMPTY_BLOB_ID`).

### External Mirroring, Caching & Backups (M5)

- **`scrim mirror`:** Enforces a minimum client Git version of **2.44.1** (`MIRROR_MIN_GIT_VERSION`, guaranteeing `GIT_NO_LAZY_FETCH=1` is honoured; all other Git-spawning CLI commands and `scrim-server` `serve`/`backup`/`restore` enforce `MIN_GIT_VERSION = 2.40.0`). Fetches server branch and withholding rules, selects only refs visible to an empty group set (case-sensitive and case-insensitive, skipping symrefs), and scans every reachable tree against server withholding rules, working-tree/.HEAD `.scrim/paths.toml`, and each commit's own `.scrim/paths.toml`. Pushes only if every matched blob is present locally and begins with `SCRIMFILE\0`, using `GIT_NO_LAZY_FETCH=1`, `--no-follow-tags`, `--recurse-submodules=no`, explicit `<ref>:<ref>` refspecs, and no Scrim bearer token in Git's environment.
- **R2 Backups & Restore:** Backups take `git clone --mirror` snapshots (stripping `remote.origin`), build deterministic `.tar.gz` archives (`follow_symlinks(false)`), invoke `pg_dump`/`pg_restore` via `env_clear()` with `PG*` env vars only, and publish `latest.json` only after all artifacts and `manifest.json` succeed. Restores validate manifest version (`BACKUP_MANIFEST_VERSION = 1`), IDs, repo keys, and nested-repo collisions; verify exact size and SHA-256 on disk before extraction or `pg_restore`; cap extracted entries (`MAX_ARCHIVE_ENTRIES = 10_000_000`) and bytes (`MAX_EXTRACTED_BYTES = 64 GiB`) against gzip bombs; reject traversal/absolute/non-UTF-8/backslash paths; and accept only regular files and directories (blocking symlinks, hard links, FIFOs, and device nodes).

## 5. Non-Goals, Trade-offs & Known Residual Oracles

Scrim explicitly documents the following limits and residual risks (also reflected in [SECURITY.md](../SECURITY.md)):

1. **Previously decrypted content persists after revocation:** A revoked member retains any plaintext secrets, private files, or branch commits they already decrypted or fetched prior to revocation. Key rotation (`rotate_scope`, `rotate_group_key`) blocks decryption of *subsequent* commits and lists `rotated_secret_keys` / affected files so operators can rotate upstream credentials at their source.
2. **Deterministic AES-256-SIV reveals content equality:** Encrypting identical plaintext under the same `(group, generation, repo_relative_path)` produces byte-identical ciphertext. This is an intentional trade-off so `git status` stays clean and unmodified files do not churn on re-clean.
3. **File metadata remains visible:**
   - **M3 encrypted private files** do not hide repository paths, directory structure, commit history/authors/timestamps, or approximate plaintext sizes (`plaintext.len() + 16B SIV tag + header`).
   - **M4 server-side withheld files** withhold blob bytes, but non-members still receive commit and tree objects, exposing withheld file paths and blob SHA-1 object IDs in trees.
4. **Shared objects across branches:** Commits, trees, or blobs reachable from both a private branch and a visible branch are visible to anyone who can fetch the visible branch.
5. **`index-pack` `REF_DELTA` existence/size oracle (pre-hook):** As documented in [crates/scrim-server/src/pre_receive.rs](../crates/scrim-server/src/pre_receive.rs), Git runs `index-pack` before `pre-receive`. A pusher who supplies a thin pack referencing a known object ID as a `REF_DELTA` base receives `"unresolved deltas"` / `"bad object"` if the object does not exist versus `"failed to apply delta"` if it exists with a different size—allowing an existence and size probe for an already-known OID. **No object content is ever leaked**, and Check 3 / Check 6 rejects the push.
6. **Unreachable blobs & SHA-1 scope in M4:** `find_withheld_only_blobs` walks history reachable from `visible_refs`; unreachable/dangling pre-GC blobs in the bare repository's object store are not indexed by path. Additionally, `gix` in `scrim-server` is compiled with `features = ["sha1"]`, so M4 withholding supports SHA-1 repositories only.
7. **Redis epoch-bump failure TTL window:** In `CachedPolicyStore::invalidate_after`, if PostgreSQL commits a policy or group mutation and the subsequent Redis `INCR` (`scrim:policy:v1:epoch`) fails, the mutation remains committed and stale `MemberRepoPolicy` entries may remain cached until `DEFAULT_POLICY_CACHE_TTL_SECONDS` (`60s`) expires (a warning is logged). **Token and SSH-key authentication/revocation bypasses Redis entirely and is never stale.**
8. **Secret scanner bounds (`pre-receive` Check 5):** Scans only new commits (max `MAX_SCANNED_COMMITS = 4096`), the first `1 MiB` of non-binary blobs, `.env` filenames, and 7 specific credential prefixes. It is a guardrail against accidental leaks, not a general-purpose entropy or secret scanner, and is overridable with `-o scrim.allow-secret-scan=true` (audited).
9. **Transport & host assumptions:** `scrim-server` binds plain HTTP (`127.0.0.1:8080` default) and relies on a TLS-terminating reverse proxy in production; remote PostgreSQL connections require `sslmode=verify-full` (and `sslrootcert` as needed) because libpq's default `prefer` silently falls back to unencrypted, unauthenticated connections. Host OS isolation, container volume permissions, and R2 bucket IAM policies lie outside the application boundary.
